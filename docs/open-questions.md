## 已确定

| 决策 | 结论 |
| --- | --- |
| 语言 | **Go**（首选） |
| 命令面 | 4 个动作：`switch` / `import` / `remove` / `init`；裸 `eqm` = 概览 + 帮助 |
| 交互形态 | 行内提示，不做全屏；列表用上下键移动 + 直接打字过滤（参考 `gh auth login`） |
| 路径输入 | 手输 + Tab 补全 + 拖拽或粘贴文件（显示为 `[文件名]`） |
| 初始化时校验 | 目录存在性、能否找到 `config.txt`、非 ASCII 警告、可写性，全部当场反馈 |
| 当前配置失效时 | 自动退回原声（Original）并提示，不留悬空引用 |
| 运行时指针文件 | `eqm\current.txt` 放在 Equalizer APO 的 config 目录树内（已核实：APO 只监视这棵树，放外面不会自动重载），库仍在 eqm 存放目录 |
| Include 嵌套 | 已核实支持（深度上限 100，无环检测），所以我们用两层：`config.txt` → `eqm\current.txt` → 库里的 `eq.txt` |
| 界面语言 | 中英双语，默认跟随系统显示语言，环境变量可覆盖；文案不硬写 |
| 概览页 | 裸 `eqm` 显示版本号 + 当前配置 + 两个目录 + 命令列表 |
| 不做 | 独立自检命令、系统文件对话框、GUI、后台常驻、EQ 参数编辑 |
| 库的选择、退出码、文件格式等实现细节 | 见 `docs/tech-notes.md` |

## Q4 取消独立自检命令之后，剩下的两个小问题

原本设想的 `check` / `doctor` 已取消：它能查的东西都已有归属——目录与字符问题归 `init`
当场校验，`Include` 与其指向的文件归程序内部自愈（见 `design.md` 3.6 与第 6 节原则 6），
权限问题归 `init` 的写入校验。唯一剩余价值是「Equalizer APO 重装或服务被禁用」这类
外部原因，而这大多无法可靠检测。因此「怀疑出问题」时的正确动作是**重跑 `eqm init`**，
它本身就是「校验 + 修复」。

剩下两个可选项：

- `show`：打印某条配置的内容（确认从 AutoEQ 下载的版本对不对）。
- `rename`：给配置改名。

**建议**：`show` 做（成本几乎为零）；`rename` 先不做，需要时再加。

| 选项 | 说明 |

## Q11 Equalizer APO 的 config 目录不可写时怎么办

已核实：为了让 APO 自动重新加载，指针文件必须写在 APO 的 config 目录树内。
默认安装位于 `C:\Program Files\EqualizerAPO\config`，普通权限写不进去
（APO 自带的配置编辑器也是这个处境）。

| 选项 | 说明 |
| --- | --- |
| A. 要求以管理员身份运行 `eqm`（建议，先这么定） | 与 APO 自己的编辑器一致；`init` 当场说清「这个目录需要管理员权限才能写」 |
| B. 引导用户把 APO 的 config 目录换到可写位置（改注册表 `ConfigPath`） | 一劳永逸，但要动注册表；文档里当作可选方案写一段 |
| C. 不写 APO 目录，切换后让用户重启 APO | 体验最差，不建议 |
